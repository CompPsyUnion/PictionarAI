****___# PictionarAI — AI or Real?

An offline quiz for the HELLO FESTIVAL booth: participants look at photographs and decide whether each one was generated by AI or captured in the real world.

## Rules

Each group shows **three pictures** at a time. The participant picks **AI** or **Real** for every picture in the group, then presses **Submit** to score the whole group at once.

- A group counts as clean only when **all three** pictures are judged correctly.
- **Two clean groups in a row** passes the challenge.
- Any single mistake resets the streak to zero.
- Each round runs on a **60 second** clock; when it reaches zero the round ends.

Pictures never repeat within a round. Once the library is exhausted it is reshuffled, so a long round can keep going.

The app does not verify whether a picture was really AI-generated: the labels in the manifest are the answer key. No names or scores are collected, and nothing is uploaded anywhere.

## Managing the picture library

Pictures live in two folders and are declared in `pictures.json`:

```
assets/pics/ai/       pictures generated by AI
assets/pics/real/     authentic photographs
pictures.json         the manifest that lists them all
```

`pictures.json` maps each picture path to whether it is AI-generated:

```json
{
  "assets/pics/ai/01.png": true,
  "assets/pics/real/01.jpg": false
}
```

`true` means AI-generated, `false` means a real photograph. Paths are relative to the project root.

**To add, replace or remove pictures:**

1. Put the image files into `assets/pics/ai` or `assets/pics/real`.
2. List them in `pictures.json` (or remove the entries you deleted).
3. Reload the page. No rebuild or redeploy step is needed beyond uploading the files.

At least **six** pictures are required, because a round needs two groups of three distinct pictures.

The admin page at `admin.html` is a read-only gallery: it lists every picture in the manifest with its thumbnail, its AI/Real label and its filename, so the library can be checked before an event. It cannot be used to add pictures — the files live on the server, not in the browser.

## How pictures are handled

Nothing is stored in the browser. The page reads `pictures.json` on start, then loads pictures straight from their paths, letting the browser's normal HTTP cache do the work.

- The first group is decoded before the start button becomes clickable, so a round never opens on empty cards.
- While a group is being answered, the next group is warmed in the background, so it is already decoded when the cards flip.
- Loading pictures does not block the welcome screen.

Because the library is part of the deployment, it is shared by every device that opens the site: upload the pictures once and all tablets see the same set. Clearing browser data, using private browsing or switching devices cannot lose the library. Keep the original image files as a backup.

## Files

| File | Purpose |
| --- | --- |
| `index.html` | The quiz: welcome, game and result screens |
| `admin.html` | Read-only picture gallery |
| `app.js` | Picture loading, screen handling and the round flow |
| `quiz.js` | The scoring engine (groups, streaks, pass condition) |
| `style.css` | All styling |
| `pictures.json` | The picture manifest |
| `assets/pics/` | The pictures themselves |
| `scripts/test-quiz.cjs` | Tests for the scoring engine |

## Tests

The scoring engine is covered by a small test script:

```bash
node scripts/test-quiz.cjs
```

It checks that two clean groups pass a round, that a partly correct group resets the streak, that pictures do not repeat while the library lasts, and that a group cannot be scored twice.****___
